# Security Policy

## Supported Versions

Security updates are provided for the latest releases on the `main` branch.

| Version | Supported |
| :--- | :--- |
| `v0.2.x` | :white_check_mark: |
| `< v0.2.0` | :x: |

---

## Reporting a Vulnerability

We take the security and integrity of **rmap** seriously. If you believe you have found a security vulnerability, please report it to us responsibly.

**Please do not report security vulnerabilities via public GitHub issues.**

Instead, please report security issues through one of the following channels:

1. **GitHub Private Vulnerability Reporting**:
   Use GitHub's built-in private reporting under the **Security** tab of this repository:
   `https://github.com/zkalves/rmap/security/advisories/new`

2. **Direct Security Contact**:
   Send an encrypted or private email to **Ezequiel Alves** at:
   `alvesel@gmail.com`
   with the subject line: `[SECURITY] rmap Vulnerability Report`.

---

## What to Include in Your Report

To help us triage and investigate the issue quickly, please provide:
- A clear description of the vulnerability and its potential impact.
- Step-by-step instructions or proof-of-concept (PoC) demonstrating how to reproduce the issue (e.g. malformed register map file or CLI command).
- The affected component (e.g., format parser, template rendering engine, GUI file loader).
- Any proposed mitigations or patch suggestions, if available.

---

## Our Commitment

- **Acknowledgment**: We will acknowledge receipt of your vulnerability report within **48 hours**.
- **Assessment**: We will assess the severity and impact, and keep you informed of our progress.
- **Fix & Disclosure**: Once a fix is developed and verified, we will publish a patch and release a coordinated security advisory crediting you for the responsible disclosure (unless you prefer to remain anonymous).
